# meshguard

Агент, который автоматически расследует аномалии межсервисного взаимодействия
и реагирует на них. Курсовая работа по дисциплине «Применение машинного обучения
для программных решений».

```
логи ──► окна 10 с ──► One-Class SVM ──► гейт сигналов ──► LLM-агент ──► политика ──► межсетевой экран
 ▲        по сервисам     (порог по FPR)    (2 из 3 окон,       │ tool calling   (guardrails)  сервисная сеть
 │                                          корреляция)         ▼                              отчёт администратору
 └──────────────────────────── хранилище логов ◄── инструменты расследования
```

1. **Обнаружение.** Поток событий агрегируется в окна по 10 с на каждый сервис
   (14 признаков: интенсивность, доли 5xx/4xx/401, задержки p50/p95, объёмы данных,
   разнообразие клиентов, доля новых маршрутов, время суток). Признаки робастно
   стандартизуются относительно базовой линии своего сервиса и подаются в One-Class SVM;
   порог калибруется на отложенных данных под целевую долю ложных срабатываний.
2. **Расследование.** Сигнал с объяснением (какие признаки и насколько отклонились)
   передаётся агенту. LLM через tool calling запрашивает логи, топ клиентов, граф вызовов,
   трассы и классифицирует инцидент: `ddos`, `brute_force`, `data_exfiltration`,
   `software_fault`, `benign`.
3. **Реагирование.** Агент блокирует адреса, изолирует сервис или отправляет отчёт.
   Каждое действие проходит детерминированную политику: без классификации — ничего,
   действие должно соответствовать типу инцидента, уверенность не ниже порога,
   внутренние и партнёрские сети защищены, критичные сервисы изолирует только человек.
   При сбое LLM срабатывает fail-safe эскалация к администратору.

## Быстрый старт

Требуется [uv](https://docs.astral.sh/uv/); Python 3.14 он поставит сам.

```bash
uv sync --all-extras
uv run meshguard train                                 # сутки нормального трафика → artifacts/detector.joblib
uv run meshguard run ddos --provider heuristic         # офлайн-демо без LLM
uv run meshguard run data_exfiltration                 # Claude (нужен ANTHROPIC_API_KEY)
uv run meshguard run software_fault --speed 20         # поток в реальном времени ×20
```

Сценарии: `ddos`, `brute_force`, `software_fault`, `data_exfiltration`, `benign`
и усложнённые варианты `ddos_residential`, `brute_force_distributed`,
`software_fault_silent`, `data_exfiltration_relay`, `benign_campaign`.

Журнал аудита каждого расследования сохраняется в `var/incidents/*.json`,
отчёты администратору — в `var/outbox/*.md`.

## Эксперименты

```bash
uv run meshguard evaluate --seeds 3                    # сравнение детекторов + графики в reports/detection
uv run meshguard benchmark --provider heuristic --suite core
uv run meshguard benchmark --provider anthropic --suite all --seeds 3
uv run --group report python docs/report/build.py      # отчёт .docx по ГОСТ 7.32
```

## LLM-провайдеры

| `MESHGUARD_LLM__PROVIDER` | Назначение |
|---|---|
| `anthropic` (по умолчанию) | Claude Opus 5.5 через Messages API: строгие схемы инструментов, кэширование промпта, серверный fallback при отказе модели |
| `openai` | Любой OpenAI-совместимый сервер (Ollama, vLLM) — логи не покидают периметр |
| `heuristic` | Детерминированный набор правил с тем же интерфейсом: офлайн-бейзлайн и тесты |

Остальные настройки — в `.env.example`.

## Структура

```
src/meshguard/
  domain.py            доменные типы: событие, сигнал, тип инцидента
  simulation/          топология сервисов, генератор трафика, сценарии инцидентов
  detection/           признаки, детектор, гейт сигналов, наборы данных, оценка
  agent/               цикл агента, инструменты, промпт, адаптеры LLM
  response/            исполнители действий и политика-ограничитель
  pipeline.py          асинхронный конвейер поток → детектор → агенты
  benchmark.py         сквозная оценка агента на сценариях с известной разметкой
  cli.py               интерфейс командной строки
docs/report/           исходник и сборщик пояснительной записки
```
